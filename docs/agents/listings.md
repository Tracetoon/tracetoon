# Catalog listings

Where Tracetoon can be listed, which file in this repository backs each
listing, and how to submit it. Most listings are not submitted yet; a person
with the right account does each submission by hand. [submissions.md](submissions.md) has the
exact text and steps for each one.

Every manifest below is generated by `scripts/agent-surfaces.ts` (description
from the same one-sentence pitch, version from `package.json`), and
`tests/agent-surface.test.ts` checks the fields each vendor's documentation
requires. The formats follow the vendor documentation as read on 2026-11-13.

**Two branches matter.** Catalogs that review a plugin get a text-only package
from the `plugins` branch (`scripts/plugins.ts`, published by the release
workflow once npm serves the version, and tagged `plugins/v<version>`): the
Anthropic directory rejected rc.38's `plugin/` for shipping launchers,
WebAssembly and fonts, Cursor ships no binaries, and the OpenAI directory takes
no hooks. Those packages run `npx -y tracetoon@<version>`. Skill-only installs
(skills.sh, `gh skill`, Gemini) keep the full, offline skill from the `release`
branch: `main` carries source only, so a copy taken from `main` stops with exit
code 3. A manifest reaches either branch only with the next tagged release.

The repository-level marketplaces serve the same text-only packages:
`.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json` take
`claude/` and `codex/` from the `plugins` branch (since 1.0.0-rc.44, the first
release whose packages run `npx` without `--prefer-offline`), and
`.cursor-plugin/marketplace.json` takes `plugins/cursor/` from `main`. The
`plugin/` manifests (`plugin/plugin.json`, `plugin/.codex-plugin/plugin.json`,
`plugin/.cursor-plugin/plugin.json`) stay on `release` for skill-only installs.

## Before submitting

- [x] Cut a release, so `plugins` carries the packages and `release` the full skill.
- [x] Replace `plugin/assets/tracetoon.svg`, a placeholder, with real artwork
      (square, at least 48×48; Codex accepts SVG). It is now the dark app tile
      from the [logo kit](../brand/README.md), generated by `scripts/brand.ts`.
- [x] Add the `gemini-cli-extension` topic to the GitHub repository.
- [ ] Check the Gemini `skills` link works from a fresh `--ref release` install
      on macOS or Linux. Git on Windows checks symbolic links out as plain
      files unless `core.symlinks` is on, so there the extension carries only
      `GEMINI.md`; the installer covers the skill.
- [ ] Ask Cursor and Kiro whether a listing can track the `release` branch.
- [x] Privacy policy: [PRIVACY.md](../../PRIVACY.md), set as `privacyPolicyUrl`
      in the Claude manifests.
- [ ] Codex: decide on a terms URL (required only for MCP plugins today) and a
      short video walkthrough.

## Validating locally

- Agent Plugins: `plugin/plugin.json` must validate against
  [plugin.schema.json](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json);
  the test checks its required keys, name pattern and that no other keys appear.
- Gemini CLI documents no `validate` command; `gemini extensions link .` from
  a `release` checkout loads the extension for a manual check.
- Cursor: `cursor/plugin-template` ships `scripts/validate-template.mjs` for its
  own layout; the test checks the same rules (kebab-case name, the manifest in
  `.cursor-plugin/`, the marketplace `source` pointing at the plugin folder,
  the logo path).
