61 real PRs from 12 repositories · each written 3 times by each system · 2 judges per provider, both orders · prbench

Most people ask the agent they are already coding with to open the pull request. We compared exactly that, with Claude Code on Opus 5.5 and Codex on Sol 6.1, against the same agent in the same session using Tracetoon. Judges preferred the Tracetoon description far more often, it scored about 15 points higher on a 100-point quality scale, and it carried fewer factual errors. It also cost less: your session's model only coordinates, while a fresh drafter and two small reviewers do the writing and checking without dragging your whole conversation along. This is a separate benchmark from our evidence-graph results, which compared two versions of Tracetoon.

Quality

Each PR was written three times by each system and scored against an expert-reviewed fact sheet: did it convey the key facts, the context and the open questions, how did it do on a 10-item reviewer rubric, and did it make errors. Two judges per provider (Opus 5.5 and Sonnet 5.5 for Claude Code, Sol 6.1 and Terra 6.1 for Codex) read every pair in both orders; a pick only counts when both judges agree in both orders.

The biggest gains are in context (why the change was made, from the session) and in avoiding errors. Tracetoon's PR also lists the checks it actually ran on the submitted code, so the Validation section says what passed instead of what probably would. Tracetoon wins on 52 of 61 PRs on Opus and 57 of 61 on Sol. On the 53 PRs outside the eight hard cases we used for early smoke tests, the margins hold: +13.9 and 60–9 on Opus, +14.8 and 98–16 on Sol.

Cost

An agent that has been coding for a while carries a long conversation. Every request it makes re-reads that context from the cache. We priced every model request in the recorded runs at list prices, assuming a session that carries 500k tokens, with Claude Code's subscription caching (your main conversation cached for an hour, subagents for five minutes) and Codex's 30-minute cache.

Writing a PR alone, Opus made 10 requests on your main session and Sol 30, each one carrying the whole conversation. With Tracetoon your session makes about 4 to 6: it prepares the evidence brief, starts the drafter, and relays the link. The drafting happens in a fresh context that holds only the brief and the diff. Counted without any carried session, Tracetoon costs more than the agent alone ($0.53 vs $0.27 on Opus), because it does more work: it runs the checks and two reviews. The saving comes from keeping that work out of your long conversation, so it grows with the size of your session and shrinks with a short one.

How it works

  • Your agent coordinates. One command builds the digest and the evidence brief from your session logs (a deterministic step, no model call). Your agent then starts one drafter and waits.
  • A fresh drafter writes. It runs on your session's model at low effort, reads the brief and the diff, runs the repository's checks, and drafts the description.
  • Two small reviewers check. Haiku on Claude Code, Luna on Codex, at extra-high effort: one looks for missing behaviour, one checks every claim against the diff. The drafter applies one correction pass and publishes the PR.

Method and caveats

  • Same agent, same session, same models. The native arm is Claude Code 2.1.319 (Opus 5.5) or Codex 0.169.0 (Sol 6.1), asked to open a PR for the branch with no skill installed. In the benchmark, long test commands run in the foreground for every Claude Code system, so neither arm ends a run waiting on a background job.
  • The 500k-token session is an assumption. With a smaller session the saving shrinks; with none, Tracetoon costs more than the agent alone. Haiku's cache prices use the standard multipliers.
  • Errors. The error figures are the judges' raw counts for both sides. An expert accuracy review of Tracetoon's flagged claims confirmed 111 of 144 on Claude Code and 56 of 78 on Codex; the native drafts were not separately reviewed.
  • In-sample. These 61 PRs were also used to develop Tracetoon. This setup was chosen on one-draft panels over all 61 PRs and confirmed here on three drafts each.
  • Not covered. On Sonnet 5.5, Tracetoon's PRs are far better than Sonnet's own short descriptions (judges 57–0 in a one-draft panel), but cost more, because Sonnet alone writes very little. Drafting with Sonnet under an Opus session was cheaper still but barely better than Opus alone.
