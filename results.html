Tracetoon vs your agent alone

Most people ask the agent they're already coding with to open the PR. So we compared exactly that: Claude Code on Opus 5.5 and Codex on Sol 6.1 writing the PR on their own, against the same agent in the same session using Tracetoon. Each PR was written 3 times by each system and judged blind.

The evidence graph on 61 real PRs

Tracetoon against its own earlier self: the evidence graph and a single writer, against the original multi-agent workflow that re-read the logs at every step. Run on 61 real PRs from 12 repositories, with fact sheets reviewed by experts.

Not perfect yet: on Codex the graph drafts carried more confirmed factual errors (0.33 vs 0.16 per PR), and on Claude Code they conveyed slightly fewer key facts (73% vs 77%). The report lists every criterion.

Where it started: the first evidence graph

The first test of the idea. We put a deterministic evidence graph, built in the embedded Relate database, between the session logs and one mid-size writing model, and judged it against Tracetoon's full multi-agent workflow. It was a small test; the 61-PR report above repeats the comparison at scale.

How we test

prbench replays real pull requests from their recorded agent sessions, has each system write the description several times, and asks judges from two providers to compare them blind, in both orders. A pick only counts when both judges agree.

What prbench measures, and how to run it yourself →

  • Fact sheets checked by expert reviewers, so "key facts conveyed" means something
